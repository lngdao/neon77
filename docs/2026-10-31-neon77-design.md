# neon77 — cyberpunk theme + animated ASCII companion for Claude Code

Date: 2026-10-31. Owner: Long Dao. Target: Claude Code 2.1.303, terminal Ghostty 1.2.3
(truecolor, no tmux), macOS. Classic renderer today; must also work under `/tui fullscreen`.

## Intent

Make day-to-day work in Claude Code less boring: a "terminal from 2077" look, with a small
ASCII cat living in the band above the prompt that reacts to what Claude is doing, plus a
rich status line under the prompt. Everything first-party: a custom theme JSON, one mod
(plugin with a hooks module), one status line script. No third-party skin repos.

Explicitly unrelated to the owner's trading or kairos projects: no market data anywhere.

## Goals

1. A coherent neon cyberpunk theme (`neon77`) applied to the whole interface.
2. An animated ASCII cat above the prompt with many actions, driven by real session state.
3. Cyberpunk-flavoured spinner and turn-end lines.
4. A two-line status line showing model, context, cost, uptime, cache, git, effort, clock.
5. Zero friction: survives restarts, hot-reloads during development, toggleable.

## Non-goals (v1)

- No sound. No PNG/kitty images. No re-rendering of transcript messages or tool rows.
- No network calls, no external processes except the status line's `git`.
- No desktop/VS Code surfaces: terminal only (other surfaces must get `next(e)`).

## Anti-goals (a failure even if it works)

- Steals keyboard focus from the prompt, or blocks/delays any tool call.
- A crash in the band or spinner hook leaves the engine's own UI broken (hooks must
  catch and fall back to `next(e)`).
- Measurable CPU drain while idle (idle tick must be >= 3 s; sleep tick >= 2 s; no timer
  while the band is hidden).
- Eats the screen on a small terminal (see size rules).
- Flicker or layout jump in the classic renderer caused by band height changing every tick:
  the band's row count must be constant within a state.

## Constraints and facts the builder relies on

- Mods API: `on(event, matcher?, ($, e, next) => ...)`; elements from `$.ui.resolve(e)`;

  `suggestion`, `success`, `error`, `warning`, `permission`, `planMode`, `autoAccept`,

## Part 2 — Mod `neon77`

### 2.1 Band above the prompt (`ui.render` on `AbovePrompt`)

Three rows, constant height. Left: the cat (18 columns). Right: the readout. Layout at
`bodyColumns >= 70`:

```
    |\__/,|   (`\   ░▒▓ NEURAL LINK 34% ▓▒░  ICE 03  UP 00:42:17   ｱｶ7fﾃ3eｻ
  _.|o o  |_   ) )  > jacking into shell...
-(((---(((--------  last turn +12.3k tok · 4 tools · 18s
```

- Row 0 readout: `NEURAL LINK <ctx%>` (from `$.session.usage().context.percent`, refreshed on
  `turn.complete` like token-weather), `ICE <tool calls this turn, 2 digits>`, `UP hh:mm:ss`
  session uptime, then a "data rain" column of 8 random katakana/hex glyphs that shifts one
  glyph per tick.
- Row 1: the current action or speech line, prefixed `> `.
- Row 2: last-turn stats (`+tokens · tools · seconds`), or in SLEEP a matrix-rain strip.
- `bodyColumns` 45..69: drop the data rain and row-2 stats. Below 45: cat only plus the
  speech line on row 1. Never render more than 3 rows. If `e.props.hasSurvey` or the pet is
  off: `next(e)`.
- Colors: cat in `claude`; labels `inactive`; values `suggestion`; `warning` when ctx >= 70;
  `error` when ctx >= 85 (DANGER); speech in `text`; success lines in `success`.

### 2.2 State machine

States: BOOT, IDLE, SLEEP, DEEP_SLEEP, THINKING, TOOL, SUCCESS, ERROR. DANGER is a modifier
flag (ctx >= 85%) overlaid on any state. Transitions:

| From | Event | To |
|---|---|---|
| (load) | `session.start` | BOOT, 2 s, then IDLE |
| IDLE/SLEEP/DEEP_SLEEP | `prompt.submit` or `turn.start` (main loop only, `!e.agentId`) | THINKING |
| THINKING | `tool.call` begins | TOOL (remember tool name); tool count++ |
| TOOL | `tool.call` resolves (await `next(e)`) | THINKING; if `ran.isError` or `ran.deny` then ERROR 1.5 s then THINKING |
| THINKING/TOOL | `turn.complete` (main loop) | SUCCESS 2 s then IDLE |
| IDLE | 120 s with no prompt | SLEEP |
| SLEEP | 600 s total idle | DEEP_SLEEP |
| any | ctx >= 85% | DANGER flag on; off when < 80% |

Subagent turns (`e.agentId` set) never change state; they may bump a "netrunners deployed"
counter shown in SUCCESS speech.

### 2.3 Tick rate and action pools

A `$.clock` timer per state; every tick picks a frame and calls `$.ui.invalidate('ui.render')`.
Intensity multiplier from `/neon77 calm|normal|hyper` = 2x / 1x / 0.5x of the intervals.

| State | Tick | Pool (random, weighted) |
|---|---|---|
| BOOT | 500 ms | 4 readout lines in order: `BOOTING NEURAL INTERFACE...`, `LOADING PERSONALITY MATRIX... OK`, `LINK ESTABLISHED`, `> hello, choom.`; cat eyes `- -` then `o o` |
| IDLE | 3000–5000 ms random | blink (2 frames @150 ms), look left `< <` / right `> >`, tail swing (2 frames), groom (`- -` + `ω`), coffee (`c[_]` beside tail, "sipping synth-coffee"), watch rain (`> >`, "watching the rain"), doomscroll (visor `[==]`, "scrolling the net"), yawn (`O O` → `- -`), stretch (whole cat shifted right 1 col for 2 frames), purr ("prrrr"), plus a random speech line 1 in 4 ticks |
| SLEEP | 2000 ms | eyes `- -`, `z` / `Z` / `zZ` cycle after the tail, row 1 `> sleeping... (type to wake)` |
| DEEP_SLEEP | 2000 ms | as SLEEP; row 2 becomes a full-width matrix-rain strip |
| THINKING | 250 ms | typing: row 2 keyboard `-((( ▓▓▓ (((-----` with the ▓ cycling ▓▒░; eyes alternate `@ @` / `o o`; row 1 `> decrypting` + spinner glyph `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` |
| TOOL | 250 ms | typing as THINKING; row 1 label by tool: Bash → `jacking into shell`, Edit/Write/MultiEdit/NotebookEdit → `rewriting reality`, Read/Grep/Glob → `scanning sectors`, Agent → `deploying netrunner` + drone `-=[o]=-` crossing row 0 right-to-left, WebFetch/WebSearch → `surfing the net`, anything else → `running daemon <tool>` |
| SUCCESS | 250 ms for 2 s | dance: eyes `^ ^`, tail frames A/B alternating, cat shifted 0/1 col; row 1 a success line |
| ERROR | 250 ms for 1.5 s | glitch: eyes `x x`, 2 of 3 rows shifted ±1 col, 3–5 cat chars replaced by `▓▒░#%@`, row 1 an error line in `error`; `!!` above the head |
| DANGER modifier | — | eyes `O O;` (sweat), readout values in `error`, row 1 prefix `COMPACT IMMINENT · ` |

Easter eggs: on each IDLE tick, 1 % chance of one: drone pass (6 frames @150 ms), `WANTED`
flash on row 0 for 1 frame, the cat becomes `(=^.^=)` for 1 frame, `NO SIGNAL` static on all
rows for 1 frame.

### 2.4 Speech lines

About 30 short lines, cyberpunk register, English with a few Vietnamese ones; original
text, no film quotes. Three pools: idle (e.g. `the net is quiet tonight`, `rain again. always
rain.`, `ice cold out there, choom`, `bạn ổn chứ?`), success (`clean run. no ICE tripped.`,
`daemon compiled, ship it`), error (`ICE bit back`, `signal lost… reconnecting`). Builder
writes the lists; keep each under 40 characters.

### 2.5 Spinner and turn-end rewrite

- `ui.render` on `Spinner`: `next({ ...e, props: { ...e.props, word: verb, suffix: ' ▓▒░' } })`
  where `verb` is sampled once per turn at `turn.start` from ~20 verbs: Jacking in, Breaching
  ICE, Decrypting, Compiling daemons, Overclocking, Scanning the grid, Rerouting power,
  Patching the matrix, Negotiating with the mainframe, Hotwiring, Spoofing, Bypassing
  firewall, Syncing neural link, Defragging reality, Rendering Night City, Hacking the
  gibson, Reading the chrome, Charging capacitors, Tuning the deck, Ghosting.
  Honour `e.props.message` when set (do not override an engine override).
- `ui.render` on `TurnDuration`: rewrite `word` to a matching past tense (`Jacked in`,
  `ICE breached`, `Daemon compiled`, …).
- Fallback outside the mod: `spinnerVerbs: { mode: "replace", verbs: [same list] }` in
  settings.json so the vibe survives with the mod disabled.

### 2.6 Commands, toggles, persistence

- `$.command.register({ name: 'neon77' })`; `command.run` handles: no arg → help text;
  `on` / `off` → pet visible; `calm` / `normal` / `hyper` → intensity; `pet` → force a random
  IDLE action now. Settings live in `$.store` (persist across sessions) and mirror into
  `$.state` atoms for rendering.
- If the build's `userConfig` supports toggle/enum rows, also expose `pet` and `intensity`
  in `/config`; otherwise the command alone is enough. Builder's choice.
- Toast on `turn.complete` only when the turn took > 60 s: `that took <n>s, choom.`

### 2.7 Quality bar

- `claude plugin validate <mod>` clean; `tsc -p <mod>` clean once types are laid.
- Tests via `claude plugin test`: state transitions for the event sequence
  start → prompt.submit → tool.call(Bash) ok → tool.call(Edit) error → turn.complete; band
  render returns a 3-row tree and `next(e)` when the pet is off or `hasSurvey`; Spinner
  rewrite keeps `message` when present; width 40 renders cat-only.
- Every hook wraps its body in try/catch and returns `next(e)` on failure.

## Part 3 — Status line (`~/.claude/neon77/statusline.sh`)

Registered in `~/.claude/settings.json`:

```json
"statusLine": { "type": "command", "command": "~/.claude/neon77/statusline.sh", "padding": 0 }
```

Two lines, ANSI truecolor matching the theme, separators `▓`:

```
▓ glm-5.1 ▓ CTX ████████░░░░ 67% ▓ $0.42 ▓ 00:42:17 ▓ CACHE 91% ▓
▓ main +3 ~2 ▓ EFFORT max ▓ FAST off ▓ 23:41 NIGHT CITY ▓
```

- Context bar 12 cells; colour cyan < 50 %, yellow < 80 %, pink/red >= 80 % plus the word
  `COMPACT!` at >= 85 %.
- CACHE: `hit_ratio` as a percent when `warm`, `cold` when not warm, `--` when absent.
- Git: branch, `+n` staged, `~n` modified; computed in `workspace.current_dir`; cache the
  git result for 5 s in a temp file so big repos do not stall the status line; skip when not
  a repo.
- Cost is Claude Code's own list-price estimate and will be off through the anyrouter
  aliases; show it as-is. (Owner may add `modelPricing` later; out of scope.)
- Dependency: `jq` if present, else a Python 3 fallback; builder checks what is installed.
- Note for the owner: a custom status line hides most footer keyboard hints by design.

## Part 4 — Install steps the builder performs

1. Write the theme file; set `theme`, `statusLine`, `spinnerVerbs` in `~/.claude/settings.json`
   (edit in place, keep all other keys; back the file up first).
2. Write the mod in the dev-mods folder; hot reload is the owner's prompt to accept.
3. Write and `chmod +x` the status line script; test it with a sample JSON on stdin.
4. Tell the owner: restart once for the theme folder; optional `/tui fullscreen`.
